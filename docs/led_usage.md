# LED Device Usage

LEDの制御には、表示パターン、点灯モード、色等CAN通信で送るには情報や提供するべきAPIが多すぎる。
そのため、gn10-canのLEDではそれぞれのロボットでカスタムの情報を集めた構造体を作成し、その構造体を送受信する仕組みを取る。
ここでは送信側と受信側の構造体が一致することが条件である。

構造体の例：
```c++
struct LEDDisplayInfo {
    bool communication_status;
    uint8_t power_level;
}
```

上のような構造体を作成して、LEDServerでは受け取った構造体をもとにLEDを制御するという方法である。
この方法ではLEDの光らせ方は送らずに、光らせ方を決めるために必要な情報を送信するため、
送信側はLED制御ではなく、表したい情報に専念できる。
受信側は多くのパターンに対応することなく、自由な光らせ方を実装できる。
というメリットが得られる。
また、通信面ではLEDの情報ではなく表示する情報に限定され通信容量を削減することができる。

そして何よりもAPIがシンプルでどのチームでも使用することができる。
